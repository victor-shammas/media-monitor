# Enrichment Pipeline: How Daily Enriched Files Are Built

This document describes how raw article data (titles, URLs, full-text extracts, AI summaries) is captured and persisted in the private `media-monitor-data` repository.

## Where the files live

```
data-private/enriched_YYYY-MM-DD.json
```

- One file per **article publication date** (UTC), not per scrape date.
- `data-private/` is a git submodule pointing at the private repo [`victor-shammas/media-monitor-data`](https://github.com/victor-shammas/media-monitor-data).

## Who writes them

`article_scraper.py:run_scraper()`, invoked by `media-monitor.py --enrich`. The `Media Monitor Pipeline` GitHub Action runs this on a schedule with `--enrich-hours 24`.

## End-to-end flow per pipeline run

1. **Read** `data/monitor_state.json` — the public DB of every article ever seen across all feeds. This file is populated earlier in the same script by the RSS fetch step (Google News per country).

2. **Pick candidates** — every article whose `date` field is within the last 24 hours.

3. **Skip already-processed** — for each candidate publication date, load the existing `enriched_YYYY-MM-DD.json` from `data-private/` and drop any article whose `google_url` is already present.
   *Dedup key: `google_url` (the raw Google News redirect URL).*

4. **Process each remaining article** (`article_scraper.py:464+`):
   1. Build a record skeleton with `title`, `source`, `google_url`, `date`, `category` and placeholders.
   2. Run **blocklists** (source, title-pattern, URL). Hits short-circuit with `extract_status = blocklisted_*` and skip the rest.
   3. **Resolve the Google News redirect** via `googlenewsdecoder` → `resolved_url`. Failure sets `extract_status = resolve_<reason>`.
   4. **Extract body text** via `trafilatura.extract()` → `extract` (capped at `MAX_EXTRACT_WORDS`) plus a `word_count`. Sets `extract_status` to one of `ok`, `fetch_failed`, `too_short`, `skipped_domain`, or `error: <msg>`.
   5. Bucket the record under `article_date_slug(record)` — the **article's own publication date** in UTC, falling back to today if the date is missing.

5. **Generate AI summaries** for every record with `extract_status == "ok"` via `generate_summaries()`. Provider order: **Gemini first, Mistral fallback**. Result lands in the `summary` field.

6. **Merge & write per-day files** (`article_scraper.py:557-620`). For each date slug touched in this run:
   - Load the existing day-file.
   - Dedup new records by `google_url` *and* normalized title.
   - Append new records to the existing list.
   - Renumber `ref` sequentially across the merged list.
   - Recompute the `stats` block.
   - Overwrite `enriched_<slug>.json` with the new content.

7. **Write summaries back to `monitor_state.json`** so the public `feeds/*.txt` show them too.

8. **Commit & push** — the workflow's "Push enriched data to private repo" step (`pipeline.yml:57-64`) `cd`s into `data-private/`, commits the changes, and pushes to `media-monitor-data`.

## File schema

### Top level

```json
{
  "generated_at": "2026-05-22 06:44:31",
  "last_updated_at": "2026-05-22 12:42:49",
  "stats": {
    "total": 312,
    "resolved": 298,
    "extracted": 271,
    "skipped": 4,
    "blocklisted": 9,
    "failed_resolve": 8,
    "failed_extract": 20,
    "summarized": 264
  },
  "articles": [ ... ]
}
```

- `generated_at` — when this date-file was first created.
- `last_updated_at` — when it was most recently merged.
- `stats` — recomputed on every merge, reflecting the *full* day-file state.
- `articles` — append-only list across pipeline runs.

### Per-article record

```json
{
  "ref": 42,
  "title": "Original RSS headline",
  "source": "extracted-source.com",
  "google_url": "https://news.google.com/rss/articles/...",
  "resolved_url": "https://realpublisher.com/article",
  "date": "2026-05-22T07:13:00+00:00",
  "category": "usa",
  "extract": "Full article body, trafilatura-extracted, word-capped...",
  "extract_status": "ok",
  "word_count": 612,
  "summary": "AI one-paragraph summary generated by Gemini/Mistral."
}
```

| Field | Meaning |
| --- | --- |
| `ref` | Sequence number within this day-file (renumbered on every merge). |
| `title` | Original RSS title. |
| `source` | Domain/source name extracted from the title. |
| `google_url` | Original Google News redirect URL. **Primary dedup key.** |
| `resolved_url` | Final publisher URL after redirect resolution; `null` on failure. |
| `date` | Original RSS publication timestamp (ISO 8601, UTC offset). |
| `category` | Feed of origin (`usa`, `uk`, `france`, …). |
| `extract` | Full-text body from `trafilatura`, capped at `MAX_EXTRACT_WORDS`; `null` if extraction failed or was skipped. |
| `extract_status` | One of: `ok`, `skipped_domain`, `blocklisted_source`, `blocklisted_title`, `resolve_<reason>`, `fetch_failed`, `too_short`, `error: <msg>`. |
| `word_count` | Word count of `extract`. |
| `summary` | AI-generated one-paragraph summary; `null` if no extract or summarization skipped. |

## Mental model

- **One file per publication day**, not per scrape day.
- **Articles are append-only** within a day-file across pipeline runs.
- **Dedup is two-layered**: `google_url` (primary) and normalized title (secondary, prevents the same story arriving under two URLs).
- **`extract` + `summary` are the substantive content** — every downstream generator (`actors_generator.py`, `hotspots_generator.py`, `radar_generator.py`, the daily report) reads this data via `ai_reporter.load_enriched()`.

## Key files

| File | Role |
| --- | --- |
| `media-monitor.py` | Top-level CLI; orchestrates RSS fetch + `--enrich` step. |
| `article_scraper.py` | All of `run_scraper()`, URL resolution, extraction, summarization, merge-and-write. |
| `ai_reporter.py` | `load_enriched()` — how downstream generators consume the day-files. |
| `monitor_utils.py` | Shared helpers (`get_sort_time`, `normalize_title_for_dedup`, category labels). |
| `.github/workflows/pipeline.yml` | The Action that runs the enrichment and pushes `data-private/`. |
| `data/monitor_state.json` | Public master DB of RSS items + (eventually) their summaries. |
| `data-private/enriched_YYYY-MM-DD.json` | Private per-day enriched files described above. |
